# Ce que pèse Lucivy_Scope, document par document (base du dépôt, 14 novembre 2026)

Pour la page de règles d'exclusion de recherche. Ticket : `docs/lucivy/tickets/2026-11-13-le-plein-texte-du-depot-pese-cent-fois-ses-sources.md`.

## En bref

- **89894 documents vivants, 927.6 Mo de texte** (champ `content`).
- **Les documents minifiés portent 92.3 % du texte** (856 Mo, 10677 documents). Le code « source » n'en fait que 67 Mo.
- **Les doublons exacts gaspillent 844 Mo** : 2588 contenus répétés, 18862 documents de trop. Le même morceau de 133 Ko revient jusqu'à 484 fois.
- **Le mécanisme** (déduit des données, à confirmer dans le code de rag3weaver) : dans un bundle JavaScript minifié, tout le code tient sur une ligne. Chaque fonction de cette ligne devient un scope, et le contenu d'un scope est fait des **lignes** qu'il couvre. Les centaines de fonctions de la ligne reçoivent chacune la ligne entière. D'où des centaines de copies de 133 Ko, sous des noms d'une ou deux lettres (`ug`, `fo`, `ef`… : les noms minifiés).
- **Deux règles régleraient l'essentiel** : ne pas indexer les fichiers minifiés, ou limiter le contenu d'un scope à ses propres octets plutôt qu'à ses lignes.

La nature est **devinée par le contenu**, pas par le chemin : « minifié » = une ligne d'au moins 1 000 octets et moins de 12 % d'espaces, ou une `sourceMappingURL` ; « généré » = « generated » ou « do not edit » dans les 4 000 premiers caractères ; « importé ? » = « copyright » ou « license » au même endroit (un en-tête de licence n'est pas une preuve d'import) ; « source » = le reste.

## Limites de cette mesure

- **Les documents de `Lucivy_Scope` ne portent pas de chemin de fichier** (champs `content`, `docstring`, `name`, `_org`, `_project`). Le chemin est dans le graphe. Le lien est le `_node_id`, l'offset de la ligne `Scope` : **le texte par dossier se fait par jointure dans le graphe**, avec le tableau complet ci-dessous.
- La copie compte 89 894 documents vivants, contre 68 585 `Scope` annoncés par `daemon_status` pour le backend `rag3db` : ce `.fts` n'est sans doute pas celui du backend ouvert (sonde de hotfixs en cours).
- Le tableau complet, une ligne par document (shard, `_node_id`, octets, nom, plus longue ligne, part d'espaces, marques, empreinte, première ligne), est hors du dépôt : à luciepc, `~/.cache/rag3weaver-build/mesure-fts/documents.tsv` (89 895 lignes). Il a été produit par `diag_documents_tsv` (branche lucivy `diag-poids-du-texte`, e0a318c), sur une copie de la copie par reflink du 14 novembre à 13 h 08.
