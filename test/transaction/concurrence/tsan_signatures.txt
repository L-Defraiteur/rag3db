# Les courses connues que ThreadSanitizer voit dans C5 et C6, une signature par ligne :
# le type, puis les deux accès, chacun par son premier cadre dans src/ (fonction et
# ligne). La passe concurrence_tsan.signatures échoue sur toute signature de C5 ou C6
# absente d'ici ; une signature d'ici qui n'est pas revue n'est pas un échec. Mesuré
# le 3 octobre : ces signatures sortent dès la première passe de dix répétitions, et les
# mêmes sur cinq passes. Une ligne ne se retire que dans le commit de la marche qui
# supprime la course (A5 pour VectorVersionInfo::delete_ et l'initialisation paresseuse
# de initDeletionVersionArray). C7 n'est pas comparé (voir compare_tsan_signatures.py).
#
# Marche A5 (3 octobre) : les six signatures de C5 et C6 — VectorVersionInfo::delete_,
# initDeletionVersionArray, isDeleted, isSelected — ont disparu avec le verrou des
# informations de version (ChunkedNodeGroup::versionInfoMtx). La liste est vide : toute
# signature de C5 ou C6 est désormais un rouge.
